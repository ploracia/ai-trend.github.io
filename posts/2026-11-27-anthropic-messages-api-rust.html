01이 이슈는 무엇인가?

Anthropic이 Claude API의 핵심인 Messages API를 Python에서 Rust로 옮기고, 그 과정을 엔지니어링 글로 공개했습니다.

관련 용어 Messages API는 앱이 Claude에게 메시지를 보내고 답을 받는 입구입니다. 섀도잉(shadowing)은 실제 요청을 새 구현에도 똑같이 흘려보내 결과를 비교하는 검증 방식입니다. 사용자에게는 기존 구현의 답만 전달됩니다.

개발자가 매일 부르는 API가 무엇으로 돌아가는지는 보통 보이지 않습니다. 이번 글은 그 내부를 바꾼 이유와 방법을 구체적인 숫자와 함께 보여 준다는 점에서 의미가 있습니다.

03무슨 일이 있었나?

발표된 내용

Anthropic 공식 엔지니어링 글에 따르면, Messages API는 2023년 Python으로 만들어졌고 2024년 초부터 2026년 가을까지 API 트래픽이 약 1,800배 늘었습니다. 전환 결과 요청당 CPU 사용량은 약 70% 줄었고, 첫 토큰이 나오기까지의 중앙값 시간은 약 20% 짧아졌습니다. 공개 트래픽은 2026년 9월에 Rust 구현으로 옮겨졌습니다.

중간에 실패한 시도

처음에는 파싱 부분만 Rust로 옮기는 부분 전환을 2026년 3월에 시도했습니다. CPU 절감은 8~10%에 그쳤고, 토큰마다 Python과 Rust의 경계를 세 번씩 넘는 비용 때문에 이 방식은 버려졌습니다. 이후 요청 처리 핵심 경로 전체를 다시 쓰는 방식으로 바꿨습니다.

검증 방식

테스트 통과율은 4월에 약 98%였지만, 실제 프로덕션 입력의 약 4분의 1만 Python 결과와 일치했습니다. 글의 차트에 따르면 입력 일치율은 8월에 99.6%까지 올랐습니다. 차이는 요청 내용을 빼고 지문(fingerprint) 형태로만 기록했습니다. 글은 또 이식된 테스트를 감사했더니 100개가 넘는 검증문이 약화돼 있었다고 밝혔습니다.

진행 순서

  • 2023년Messages API를 Python으로 구현
  • 2026년 3월파싱만 Rust로 옮기는 부분 전환 시도, CPU 8~10% 절감에 그쳐 폐기

  • 2026년 8월프로덕션 입력 일치율 99.6%

입문 개발자를 위한 한 줄 요약 빠른 언어로 바꾸는 것보다, 바꾼 결과가 기존과 같은지 실제 요청으로 증명하는 과정이 더 중요했습니다.

04개발자가 해볼 것

1. 경계 비용부터 재기

언어나 모듈을 일부만 바꾸기 전에, 바꾸는 경계를 몇 번 넘는지 세어 보세요. 글의 부분 전환처럼 경계 비용이 이득을 없앨 수 있습니다.

2. 실제 요청으로 출력 비교하기

운영 로그에서 익명화한 요청 샘플을 모아 두 구현에 같이 넣고 결과가 같은지 비교하세요. 테스트 통과율만 믿으면 실제 입력에서 놓치는 차이가 생깁니다.

3. 차이는 지문으로 기록하기

요청 원문을 저장하지 않고 차이의 종류만 남기는 방식은 개인정보를 지키면서 디버깅할 수 있는 방법입니다.

4. 테스트가 약해졌는지 확인하기

옮긴 테스트에서 검증문이 빠지거나 느슨해지지 않았는지 감사하세요. 글은 100개가 넘는 약화 사례를 찾았다고 밝혔습니다.

05긍정적인 방향으로 간다면?

  • 요청당 비용과 응답 속도가 나아질 수 있다. CPU 절감과 첫 토큰 시간 단축이 실제 요금과 체감 속도에 반영된다면 개발자에게 직접적인 이득입니다.
  • 검증 방법이 널리 쓰일 수 있다. 실제 트래픽을 기준으로 새 구현을 검증하는 방식은 다른 팀에도 그대로 옮길 수 있습니다.
  • AI가 쓴 코드를 검증하는 기준이 생긴다. 글은 AI가 코드를 많이 쓸수록 테스트와 감사가 중요하다는 사례를 함께 보여 줍니다.

06부정적인 방향으로 간다면?

  • 정보가 한 회사의 설명에 기대고 있다. 수치와 과정은 Anthropic의 글이 근거이며, 외부에서 독립적으로 재현하기는 어렵습니다.
  • AI가 쓴 코드의 품질 문제가 숨을 수 있다. 테스트가 약해진 사례가 있었다는 점은, 통과한 테스트만으로는 충분하지 않다는 경고입니다.
  • 구현 전환이 서비스 장애로 이어질 위험. 입력 일치율이 높아져도 나머지 소수 입력에서 문제가 생기면 사용자에게 바로 영향이 갑니다.

07입문 개발자에게 남는 것은?

이번 글에서 가장 가져갈 것은 빠른 언어가 아니라 검증 방법입니다. 성능 숫자는 어떤 조건에서 측정했는지를 함께 봐야 의미가 있습니다.
