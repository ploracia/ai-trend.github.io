01이 이슈는 무엇인가?

여러 AI 모델을 한곳에서 호출하게 해 주는 게이트웨이가, 그 뒤에 있는 추론 공급자의 보안 문제 때문에 공급자를 정리한 사건입니다.

관련 용어 추론 공급자(inference provider)는 모델을 실제로 돌려 응답을 만들어 주는 업체입니다. 데이터 보관 없음(ZDR, Zero Data Retention)은 요청 내용을 저장하지 않겠다는 계약 조건으로, 표시가 붙어 있어도 실제 보관 여부는 공급자 정책과 중계 경로에 따라 달라질 수 있습니다.

OpenRouter는 여러 모델 공급자를 하나의 API로 묶어 주는 서비스입니다. 개발자는 한 번의 연결로 여러 모델을 바꿔 쓸 수 있지만, 요청이 어느 공급자를 거치는지는 중간 단계에서 결정됩니다. 그래서 중계 공급자의 보안이 곧 개발자 데이터의 보안이 됩니다.

03무슨 일이 있었나?

보도된 내용

보도에 따르면 OpenRouter는 11월 22일 추론 공급자 3곳을 제외했고, 이 과정에서 125개 엔드포인트가 데이터 보관 없음 대상 자격을 잃었습니다. 영향을 받는 고객에게는 안내가 나갔다고 전해졌습니다. Unite AI는 이 조치가 프롬프트 노출 조사 결과 뒤에 나왔다고 정리했습니다.

이 조치의 배경으로 Dragos의 연구가 함께 소개됐습니다. The Decoder에 따르면 연구진은 약 200만 건의 가짜 AI 요청을 활용해 최소 3개 저가 공급자가 침해됐음을 확인했습니다. 연구에서는 수백 개의 AWS 키가 탈취됐고, 일부 재판매업자가 고객의 요청 내용을 읽은 정황도 나왔다고 합니다. 이 수치는 해당 연구를 보도한 매체의 설명이며, 이 글에서는 원문 연구를 직접 확인하지 못했습니다.

하루 전인 11월 21일에는 OpenRouter가 MiniMax 경로를 거친 일부 프롬프트가 읽혔을 수 있다고 고객 이메일로 알린 것으로 전해졌습니다. 이 기간에 해당 모델의 ZDR 표시는 조사가 끝날 때까지 제거됐습니다. OpenRouter는 문제의 원인이 MiniMax와 중계 공급자에 있고 OpenRouter 자체 시스템의 문제는 아니라고 설명했다고 보도됐습니다.

진행 순서

  • 2026년 11월 21일 (토)OpenRouter가 고객에게 MiniMax 경로의 프롬프트 노출 가능성을 안내하고, 관련 모델의 ZDR 표시를 제거
  • 2026년 11월 22일 (일)OpenRouter가 추론 공급자 3곳을 제외하고 125개 엔드포인트의 ZDR 자격을 해제했다고 Unite AI가 보도
  • 2026년 11월 22일 (일) 정오 무렵The Decoder가 Dragos 연구 결과를 전하며 저가 추론 공급자의 위험을 정리
입문 개발자를 위한 한 줄 요약 API 게이트웨이를 쓰면 편리하지만, 요청이 거치는 공급자까지가 내 데이터가 지나가는 범위입니다.

04개발자가 해볼 것

1. 민감 데이터가 포함된 요청은 나누기

개인정보, 고객 데이터, 사내 코드처럼 민감한 입력은 공급자 정책을 확인한 뒤에만 보내세요. 테스트용 샘플과 실제 데이터를 같은 경로로 보내지 않는 것이 기본입니다.

2. ZDR 표시를 한 번 더 확인하기

표시는 계약 조건의 요약일 뿐입니다. 조사 중인 경로나 제거된 표시가 있는지 공지를 보고, 필요하면 해당 모델을 임시로 빼 두세요.

3. API 키를 주기적으로 교체하기

키가 노출되면 피해가 커집니다. 키 권한을 최소로 두고, 사용량 알림을 켜고, 의심스러운 호출이 보이면 즉시 교체하는 절차를 만들어 두세요.

4. 입력 전에 마스킹하기

전화번호, 이메일, 토큰 같은 값은 모델에 보내기 전에 가리거나 대체하는 함수를 한 곳에 두면 나중에 공급자가 바뀌어도 영향이 적습니다.

05긍정적인 방향으로 간다면?

  • 공급자 검증 기준이 생긴다. 게이트웨이들이 공급자 심사와 제외 기준을 공개하면, 개발자가 비교할 수 있는 객관적인 자료가 늘어납니다.
  • 데이터 보관 조건이 더 세밀해진다. 모델 단위로 ZDR 상태를 보여 주는 방식이 자리 잡으면, 민감한 작업에만 안전한 경로를 고르기 쉬워집니다.
  • 침해 사실이 빨리 공유된다. 연구자와 중계 업체가 문제를 드러내고 고객에게 알리는 흐름이 굳어지면, 피해를 줄이는 속도가 빨라질 수 있습니다.

06부정적인 방향으로 간다면?

  • 저가 공급자 뒤의 위험이 가려진다. 가격만 보고 고르다 보면, 어떤 회사가 요청을 저장하거나 재판매하는지 알기 어려워집니다.
  • 키 유출이 연쇄 피해로 이어진다. 하나의 키가 여러 서비스에 쓰이면, 한 번의 탈취로 클라우드 비용과 데이터 접근이 함께 노출될 수 있습니다.
  • 책임 소재가 흐려진다. 게이트웨이, 중계 공급자, 모델 회사가 나뉘어 있으면 사고가 났을 때 누구에게 무엇을 물어야 하는지 헷갈릴 수 있습니다.
