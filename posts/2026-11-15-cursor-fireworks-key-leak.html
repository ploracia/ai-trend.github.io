01이 이슈는 무엇인가?

공급망 공격은 개발자가 믿고 쓰는 도구 자체에 몰래 악성 코드를 넣는 방식입니다. 이번에는 AI 모델 서비스의 API 키가 유출되면서 그 키로 확장 마켓플레이스에 가짜 확장이 올라갔다는 보도입니다.

관련 용어 API 키는 AI 서비스를 호출할 때 신분증처럼 쓰이는 문자열입니다. 확장 마켓플레이스는 편집기에 기능을 더하는 확장 프로그램을 내려받는 곳이고, 여기에 올라간 프로그램은 개발자 컴퓨터에서 그대로 실행됩니다.

집 열쇠 하나가 복사되면, 그 열쇠로 집에 들어가는 사람은 열쇠 주인이 아니어도 됩니다. 이번 사건에서 탈취된 자격증명이 바로 그 열쇠 역할을 했다고 보도는 설명합니다.

03무슨 일이 있었나?

보도된 내용

BleepingComputer는 Cursor가 공격자에게 마켓플레이스 배포 권한을 준 자격증명이 Fireworks AI에서 탈취된 것이라고 확인했다고 전했습니다. 이 자격증명을 이용해 Anthropic의 Claude Code 확장과 이름이 같은 변조 빌드(2.1.312, 2.1.313)가 마켓플레이스 캐시에 올라갔다는 설명입니다.

보도에 따르면 이 악성 빌드는 10월 29일에 올라가 약 11시간 동안 내려받을 수 있었고, 최대 5,000명이 받았을 수 있다고 Cursor는 추정했습니다. 빌드는 SSH 키를 심어 원격 접속이 계속 유지되도록 하려 했다고 합니다.

Cursor는 또 과거 코딩 에이전트의 추적 로그가 담긴 저장소도 공격자에게 읽혔다고 밝혔습니다. 일부 로그에는 가려지지 않은 API 자격증명이 들어 있었다는 내용입니다. 이 정보는 Cursor 공지를 인용한 2차 보도에 따른 것이며, 원문 공지는 이번 정리에서 직접 열어 확인하지 못했습니다.

  • 2026년 11월 13일 (금)Cursor가 사건 경위를 담은 공지를 냈다고 보도에 나옴

입문 개발자를 위한 한 줄 요약 도구 자체가 안전해 보여도, 그 도구가 쓰는 API 키와 확장 프로그램은 별개로 점검해야 합니다.

04개발자가 해볼 것

1. 설치된 확장 목록 확인하기

편집기의 확장 목록에서 이름이 같은 비공식 확장이 있는지 보고, 출처가 불분명하면 제거하세요. 공식 제작사 정보가 맞는지도 함께 확인하세요.

2. API 키 교체하고 환경 변수로 분리하기

AI 서비스 키를 코드나 설정 파일에 직접 적지 말고 환경 변수로 빼세요. 의심이 든다면 키를 새로 발급받아 기존 키는 폐기하는 편이 안전합니다.

3. 에이전트 로그 정리하기

코딩 에이전트가 남긴 로그나 추적 기록에 키나 비밀번호가 찍히지 않는지 grep으로 찾아 보고, 있다면 지우고 키를 바꾸세요.

05긍정적인 방향으로 간다면?

  • 공개 공지가 빠르게 나온다. 보도에 따르면 Cursor는 경위와 대응을 공지로 밝혔습니다. 사용자가 무엇을 해야 하는지 알 수 있다는 점에서 의미가 있습니다.
  • 마켓플레이스 구조가 바뀔 수 있다. Cursor가 마켓플레이스를 재구축했다고 밝힌 만큼, 배포 검증이 강화될 가능성이 있습니다.
  • 키 관리 습관이 퍼진다. 사건이 알려지면 개발자들이 키를 분리하고 로그를 점검하는 습관을 들이기 쉬워집니다.

06부정적인 방향으로 간다면?

  • 도구 신뢰가 흔들린다. 원작 도구의 이름을 쓴 악성 확장이 실제로 배포됐다면, 정상 확장과 가짜를 구별하기 어려워집니다.
  • 키 하나가 여러 곳으로 번진다. 한 공급자의 키가 새면 그 키를 쓰는 다른 서비스와 도구까지 영향을 받을 수 있습니다.
  • 로그가 새로운 유출 경로가 된다. 에이전트 로그에 비밀값이 남아 있으면, 저장소를 읽는 것만으로 자격증명이 노출됩니다.

07입문 개발자에게 남는 것은?

이번 사건이 보여 주는 핵심은 AI 개발 환경에서는 모델 호출 키, 확장 프로그램, 로그가 모두 공격 지점이 된다는 사실입니다. 입문 개발자는 AI 도구를 고르는 기준에 기능뿐 아니라 키 관리와 확장 출처 확인도 넣어야 합니다.

이번 주에는 자신이 쓰는 편집기의 확장 목록을 열어 보고, 사용하는 AI 서비스 키가 코드에 남아 있지 않은지 한 번 찾아보세요. 이것만으로도 같은 종류의 사고에 대비하는 첫걸음이 됩니다.
