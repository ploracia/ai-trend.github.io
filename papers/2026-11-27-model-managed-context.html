AI가 스스로 대화 기억을 정리하게 하면 어떻게 달라질까

Letting Models Manage Their Own Context: Where We Stand

2026.11.27 12:02 KST원문 arXiv 2611.34147
3줄 요약
  1. AI 에이전트가 긴 작업을 하면 쌓이는 대화 기록이 모델의 입력 한도를 넘는데, 지금은 보통 실행 틀(하네스)이 자동으로 기록을 요약해 줄인다.
  2. 이 논문은 반대로 모델이 "언제, 무엇을 요약하고 버릴지" 직접 정하게 하는 방식을 만들어, 자동 요약 방식과 비교했다.
  3. 예산이 빠듯할 때 모델이 직접 관리하는 쪽이 정확도가 크게 올랐고 입력 토큰도 줄었다. 다만 모델마다 습관이 달라 설계가 중요하다.

01본문 요약

이 요약은 arXiv 초록(2026.11.25 제출)을 기준으로 정리했습니다. 본문의 세부 실험 설정은 원문에서 직접 확인해 주세요.

문제 정의

AI 모델이 한 번에 읽을 수 있는 글자 양(컨텍스트 창)에는 한도가 있습니다. 문서를 찾고 코드를 고치는 긴 작업에서는 대화 기록이 금방 가득 찹니다. 지금 흔한 방식은 창이 차면 하네스가 과거 기록을 요약해 압축하는 것입니다. 이때 요약을 언제 할지, 무엇을 남길지는 모델이 아니라 하네스가 정합니다. 이 논문은 "모델에게 이 결정권을 주면 더 나아지는가?"를 묻습니다.

방법

연구진은 NVIDIA가 공개한 오픈소스 에이전트 하네스 nooa에 '컨텍스트 API'를 붙였습니다. 이 API로 모델이 스스로 기록을 압축하거나 고칠 수 있습니다. 그런 다음 두 방식을 비교했습니다. 하나는 하네스가 자동으로 관리하는 방식, 다른 하나는 모델이 직접 관리하는 방식입니다. 실험 과제는 문서 리서치와 머신러닝 엔지니어링이었고, 컨텍스트 예산은 8K 토큰부터 512K 토큰까지 여러 단계로 바꿔 보았습니다.

추가로 저자들은 추론 엔진 쪽 최적화도 봤습니다. 모델이 기록을 고친 뒤에도 바뀌지 않은 뒷부분은 이미 계산해 둔 값(KV 캐시)을 다시 쓸 수 있게 한 것입니다. 쉽게 말해 "앞부분만 바뀌었으니 나머지는 다시 계산하지 말자"는 발상입니다.

결과

초록에 따르면 컨텍스트 API를 잘 쓰는 모델은 같은 예산에서 더 높은 정확도를 냈고, 입력 토큰도 적게 쓰는 경우가 많았습니다. 특히 예산이 적을 때 차이가 컸습니다.

  • GPT 6.1은 32K 예산에서 OfficeQA Pro v2 점수가 21%에서 56%로 올랐다고 보고됐습니다.
  • Kimi는 입력 토큰을 최대 41% 줄이면서 성능이 올랐다고 보고됐습니다.
  • 모델마다 API를 쓰는 빈도, 압축을 얼마나 자주 하는지, 언제 압축을 시작하는지가 크게 달랐습니다. 프롬프트 문구를 조금 바꾸는 것만으로도 시작 시점이 달라졌습니다.
  • KV 캐시 재사용으로 요청당 프리필 연산을 최대 15% 줄였고, 정확도 변화는 측정되지 않았다고 합니다.

한계

  • 이 글은 초록 기준이라 과제 수, 반복 실행 횟수, 통계 검정 같은 세부 조건은 원문에서 확인해야 합니다.
  • 실험은 두 종류의 과제, 하나의 하네스, 특정 모델들에서 이루어졌습니다. 다른 환경에서도 같은 크기의 효과가 나는지는 알 수 없습니다.
  • "GPT 6.1은 점수가 세 배 가까이 올랐다"는 수치는 32K 예산이라는 특정 조건의 결과입니다. 모든 예산이나 모든 모델에 적용되는 숫자가 아닙니다.
  • 저자들은 모델이 스스로 컨텍스트를 관리하도록 훈련하고, 추론 엔진이 KV 캐시 편집을 지원하는 '공동 설계'가 다음 과제라고 제안합니다. 이는 아직 연구 방향에 가깝습니다.

02최종 의견

입문 개발자에게 이 논문의 핵심은 "긴 작업에서 무엇을 기억하고 무엇을 버릴지가 성능을 좌우하는 설계 문제"라는 점입니다. 지금 많이 쓰는 자동 요약이 항상 최선은 아닐 수 있다는 신호로 읽으면 됩니다. 수치는 인상적이지만 특정 모델과 예산에서 나온 결과이므로 "모든 에이전트가 그만큼 좋아진다"로 받아들이면 과장입니다.

직접 에이전트를 만든다면, 자동 요약에만 맡기기보다 목표, 결정 사항, 중요한 파일 경로처럼 꼭 남겨야 할 정보를 별도 메모로 저장하고, 모델이 필요할 때 그 메모를 불러오는 도구를 주는 방식부터 시도해 볼 만합니다. 이는 이 논문의 결과가 아니라 제 의견이며, 실제 효과는 자신의 과제에서 직접 측정해 봐야 합니다.
