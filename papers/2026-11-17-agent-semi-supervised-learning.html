AI 에이전트는 라벨 없는 데이터를 쓸 줄 알까?

AgentSSL: Can MLE Agents Leverage Unlabeled Data?

2026.11.17 12:01 KST원문 arXiv:2611.17323
3줄 요약
  1. 정답(라벨)이 붙은 데이터는 비싸서 적은데, 정답 없는 데이터는 많을 때 모델을 어떻게 잘 만들지가 문제다.
  2. 저자들은 AI 에이전트가 여러 준지도 학습 기법을 조합한 프로그램을 만들고, 그중 좋은 것을 고르는 AgentSSL을 제안한다.
  3. 12개 설정 중 8개에서 사람이 만든 강한 기준선을 이겼고 최대 21.8% 높았다. 입문자에게는 실험 설계의 일부를 에이전트에게 맡길 수 있다는 가능성을 보여준다.

01본문 요약

이 요약은 논문 초록을 기준으로 정리했습니다. 실험 세부 내용은 본문에서 따로 확인하지 않았습니다.

문제 정의

머신러닝 모델은 보통 정답이 붙은 데이터로 학습합니다. 그런데 정답을 사람이 하나씩 붙이는 일은 시간과 돈이 많이 듭니다. 반면 정답이 없는 데이터는 주변에 많이 쌓여 있습니다. 이 둘을 함께 써서 성능을 올리는 방법을 준지도 학습(semi-supervised learning)이라고 부릅니다. 문제는 어떤 준지도 학습 기법을 어떻게 조합해야 하는지 사람이 직접 골라야 한다는 점입니다.

방법

논문은 이 선택 과정 자체를 프로그램 탐색 문제로 봅니다. 쉽게 말해, 좋은 학습 코드를 여러 개 만들어 보고 그중 가장 잘 되는 것을 고르는 일입니다. AgentSSL에서는 ML 엔지니어링 에이전트가 이런 코드들을 만들고, 기존의 준지도 학습 기법들을 조합해 후보를 늘립니다. 저자들은 이 평가를 위해 ProgramSelectBench라는 벤치마크도 공개했습니다. 에이전트가 만든 프로그램과 사람이 만든 프로그램 16,977개가 들어 있습니다. 실제 문제로는 생태학의 탐지 과제에 적용했습니다.

결과

12개 설정 중 8개에서 사람이 설계한 가장 강한 기준선보다 나은 결과를 냈고, 개선 폭은 최대 21.8%였습니다. 논문은 가장 큰 병목을 프로그램 선택으로 지목합니다. 에이전트 자신의 평가 지표를 기준으로 고르면 성능이 최대 47%까지 떨어졌습니다. 즉, 후보를 만드는 것보다 좋은 후보를 고르는 것이 더 어렵다는 뜻입니다.

한계

  • 12개 설정 중 4개에서는 사람이 만든 기준선을 이기지 못했습니다. 모든 경우에 유효하다고 볼 수는 없습니다.
  • 선택 단계가 에이전트의 자체 지표에 기대면 성능이 크게 떨어진다는 점이 논문에서 확인됩니다. 실무에서는 이 부분을 따로 검증해야 합니다.
  • 초록 기준으로 정리했기에, 데이터셋의 구성과 재현 조건은 본문에서 추가로 확인이 필요합니다.

02최종 의견

입문 개발자에게 이 논문의 핵심 교훈은, 라벨이 부족할 때 곧바로 데이터를 더 모으기 전에 기존 기법을 조합해 여러 후보를 만들어 보는 접근이 가치 있을 수 있다는 점입니다. 다만 이 논문에서 승부를 가른 것은 에이전트가 똑똑하게 코드를 짠 것보다 후보를 골라내는 단계였습니다. 직접 적용한다면, 에이전트가 매긴 점수만 믿지 말고 사람이 따로 준비한 검증 데이터로 최종 선택을 확인하는 습관이 중요합니다.

과장되지 않게 보면, "12개 중 8개에서 이겼다"는 결과는 유망하지만 "언제나 이긴다"는 뜻은 아닙니다. 또한 이번 정리는 초록에 기반하므로, 실제 재현 여부는 본문과 프로젝트 페이지에서 확인해 보는 것이 좋습니다.
